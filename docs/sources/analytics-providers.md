## MPStats: что известно о API

- Базовый URL `https://mpstats.io/api/`, авторизация заголовком `X-Mpstats-TOKEN` (токен в личном кабинете: Аккаунт → API-токен).
- Коды ответа: `200`; `202` — запрос принят, повторить позже; `401` — ошибка авторизации; `429` — исчерпан лимит тарифа, в `Retry-After` секунды до повтора; `500`.
- Квоты зависят от тарифа, на странице документации их нет; проверяются методом `/api/user/check/limits`.
- Ответ категории: `data[]` с полями товара (название, выручка, продажи и др.) и `total`. Точные поля сверить по документации и реальному ответу при подключении (как с WB: запись ответа, схема Zod по нему).

## Что нужно от владельца

1. Выбрать провайдера (рекомендация — MPStats) и тариф, в котором есть API; у MPStats уточнить в поддержке лимиты API на выбранном тарифе.
2. Положить токен в `apps/worker/.env.local` (имя переменной задаст адаптер, например `MPSTATS_TOKEN`). В чат токен не присылать.
3. Решение по правилу 7 CLAUDE.md не нужно: провайдер отдаёт данные по своему API, сбор страниц мы не делаем.
